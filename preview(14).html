INTEGRITY / 03

Artifact verification

Compare a selected file against the SHA-256 fingerprint stored in an artifact record.

Fingerprint comparison

Choose a registered record and the file to compare. File processing happens locally in your browser.

Interpretation
A matching fingerprint indicates that the file's bytes match the recorded hash. It does not independently prove who created the artifact or when it existed. That requires a trustworthy record and, for public verification, a suitable external anchoring mechanism.
SYSTEM DESIGN / 04

Proposed architecture

Separate artifact handling from the integrity record and its future verification layer.

01 / INPUT

04 / FUTURE LAYER

Publish a commitment through a defined network adapter and verify against it.

Current product capabilities

✓ Local SHA-256 file fingerprinting

✓ Session-based event history
✓ File integrity comparison
✓ JSON manifest export

Integration boundary

○ Solana program and record schema
○ Wallet signing and transaction submission
○ Public timestamp and commitment lookup
○ Persistent registry and independent verification
These are future integration requirements, not active features. No wallet is requested and no network transaction is sent.
